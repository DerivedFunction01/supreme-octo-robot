# Timing-ledger Step 1 census — store map and mutation census

Findings first. Census taken 2026-11-27 against wt-timing @ 3365cee4
(read-only: code read first-hand, DBs opened `mode=ro`, no verbs run).

## Headline finding — the live todo store is the FILE store, not the DB

The plan's Step 2–3 form (columns on the DB `todos` table, one event
writer in `lib/registry/todos.py`) would land in a store **no production
code path writes**. Evidence:

- Every swept project's DB `todos` table is **empty** (0 rows, 0 events)
  except the stale in-tree instance. The live corpus is file todos:
  **1,545 todo files** under the projects' `.plans/*/todos/` dirs.
- The server's own docstring states it: `server/actions.py:120-134` —
  "The retired registry-DB todo verbs are gone: file todos are the
  store (§3.7)."
- Repo-wide grep (whole `pipeline/` tree, tests excluded): **no
  production caller** of `reg.add_todo` / `reg.set_todo_status` /
  `reg.set_todo_fields` exists. The only writers of the DB todo tables
  are those three functions themselves and the rebuild path
  (`entries.apply_export`). Their callers are tests only.
- The plan's first Ruling ("the ledger lives in the store the wb verbs
  actually resolve") therefore resolves to the **file store**: per
  project, `<root>/.plans/<bundle>/todos/<name>.md`. Steps 2–3 need a
  re-form against that store before they build; the DB-side facts are
  recorded below because the schema/export surface still carries them.

## 1. Store map

### How a verb resolves its store

CLI (`wb` shim docstring + `wbcli/context.py`):

- `Ctx.__init__` (wbcli/context.py:53-105), first match wins:
  1. `--db PATH` → that DB directly; layout = sibling `entries/` +
     `archive/`; slug derived from the parent dir name.
  2. `--root PATH` → `load_manifest(<root>/workbench.yaml)`.
  3. No `--project` → walk up from cwd for `workbench.yaml`
     (`paths.project_root_from_cwd`, via pipeline/workrecord/paths.py
     through wbcli/paths.py).
  4. Else sweep: roots = `WB_VIEWER_SWEEP_ROOTS` env (pathsep list) or
     the workspace root; `lib/discovery/sweep.sweep(roots)`;
     `--project SLUG` selects from the sweep; no selection with
     projects present is a refusal.
  Then `db_path = manifest.registry` (Ctx:103); a manifest with no
  `registry:` key refuses ("declares no registry").
- `PlansCtx.__init__` (wbcli/context.py:108-158): same ladder for the
  bundle/file-todo verbs; `plans_dir = manifest.plans or
  <root>/.plans`; `db_path = manifest.registry` (may be None — a
  registry is NOT required; only `todo import-db` needs it).
- Manifest (`lib/discovery/manifest.py:202-232`): flat `key: value`
  file; `registry:` / `plans:` are repo-root-relative paths, resolved
  absolute, escape refused. Every live manifest declares
  `registry: workbench/registry.db` and `plans: .plans`.
- Sweep (`lib/discovery/sweep.py`): a dir holding `workbench.yaml` at
  its top level is a project; canonicalized by git repo identity (a
  linked worktree never registers separately — the main checkout
  wins); scratch/dot-dir candidates pruned; duplicate slugs fold.
- Server (`server/config.py:51-61,310-311`): its own config —
  `sweep_roots` defaults to `[workspace_root]`, manifest name
  `workbench.yaml`, max depth 3, prune list, 15 s sweep TTL cache.
  Mutations resolve the project by slug from the same sweep
  (`server/actions.py`).

Re-exports: lib/writes/bundles.py:40-61 gathers B1–B4, B8 into the
one surface both the CLI and the server call — the wb shim's "exactly
one mutation path" claim holds for this surface.

**The wb-step "mint":** there is no automatic mint from a plan's
wb-step blocks. The block's `todos=` field names todo slugs that must
already exist as file todos (plan-check validates the references,
lib/plans/plan_check.py:389-409); the executing seat mints them
through B1 (`wb todo new --step N`, which sets `plan_step:`). The
`link_ref` field exists only on the DB side (A1/A3) and no production
path sets it.

**Reconciliation:** SQL grep (INSERT/UPDATE/DELETE against todos &
todo_events, whole pipeline tree) yields exactly A1–A4. Caller grep
for every function in lib/registry/todos.py and lib/writes yields
exactly B1–B8 + the A4 rebuild caller. The two lists close: no direct
SQL writers outside lib/registry, no file-todo writers outside
lib/writes + lib/drain.

## 3. Event / export facts

- `todo_events` schema (lib/registry/constants.py:89-99):
  `id INTEGER PK AUTOINCREMENT, todo_id TEXT, ts TEXT NOT NULL,
  actor TEXT NOT NULL, verb TEXT NOT NULL, field TEXT, old TEXT,
  new TEXT, note TEXT`. No from/to-state columns as such — a status
  transition is `verb='set-status', field='status', old, new`
  (todos.py:92-95). Actors are free text (`cli` default; server entry
  verbs pass `viewer`; ACTORS at constants.py:16 is the entry-side
  vocabulary). DB `todos` (constants.py:78-88) has no est / position /
  worktree columns; TODO_FIELDS (constants.py:33-34) = id, title,
  status, notes, link_kind, link_ref, created_at, updated_at,
  version. DB TODO_STATUSES (constants.py:14) = todo/doing/done —
  **no `blocked`**; the file vocabulary (lib/plans/bundles.py:43)
  has all four.
- Import (`entries.apply_export`, entries.py:596-653): rebuild-only.
  Entries/history/todos/todo_events are re-inserted verbatim from
  the export document, **event and history ids preserved**; refuses
  a non-empty target DB. There is no incremental event import.
- Export (`lib/registry/export.py:29-75` build_export): emits the
  full DB — entries (+derived/approval), history, **todos as
  TODO_FIELDS dicts, and todo_events as full row dicts** — nothing
  dropped today. `regenerate()` (export.py:82-88) rewrites
  registry.json beside the DB after every mutation verb; for file
  todos the export carries nothing (they are not in the DB).
